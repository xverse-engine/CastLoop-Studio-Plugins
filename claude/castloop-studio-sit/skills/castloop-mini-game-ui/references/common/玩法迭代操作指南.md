# 玩法迭代操作指南

## 阶段一｜新增玩法包

把 UI 框架和玩法文档直接交给 Skill。低保真可以是图片、文件或 Figma Section 链接。玩法文档建议说明输入、目标、计时、胜负、暂停和重试；UI 稿标清每个状态的触发和去向。

> 使用 CastLoop 小游戏 UI Skill 1.0。目前玩法库只有正式 Merge-2，请根据附件新增贪吃蛇，使用 snake 作为 ID。请自动归档资料并整理成独立玩法包。这次只新增玩法，我之后再提供故事资料生成预览。

交付位置在 `references/gameplay/snake/`。Skill 将原稿分别归档到 `inputs/ui/` 和 `inputs/rules/`，把链接记入 `inputs/sources.json`，并整理 `玩法定义.md`。如任务包含逻辑实现，可同时提供独立引擎和测试。参考工程里的试验贪吃蛇可供查阅。新增正式玩法包时，保留既有 Merge-2，也不动参考工程及任何故事项目。

此阶段验收资料是否齐全，页面、状态和判定是否可执行，以及玩法定义是否与原稿一致。主题、故事文案、预览面板和运行时项目注册留到阶段二。

## 阶段二｜选择故事并生成预览

提供故事封面、简介、主题色、字体、剧情插入点等资料，同时指明要用的玩法包。Skill 才把选中的玩法接入目标故事项目，在 `games/<id>/` 放引擎和视图，按需更新 `games/registry.mjs` 与 `project.json`，装配素材并生成独立 HTML 预览。接入时复用现有外壳与宿主组件，只有确实缺少共用能力时才扩展，并列明影响范围。

项目归档脚本 `scripts/intake-game.mjs` 用于阶段二，将资料复制或登记到工作项目的 `games/<id>/inputs/`。接口、依赖和验收见 [玩法接入契约](玩法接入.md)。

## 日常维护

- 改规则，更新玩法包的规则文档、独立引擎和测试。
- 改 UI 框架，更新玩法包的结构稿和状态定义。
- 明确要求替换已有玩法时才更新该玩法包。新增时若 ID 已占用，保留原包并确认新 ID。
- 已接入的故事项目按需选择何时采用更新，回归该玩法及项目内其它已启用的玩法。
