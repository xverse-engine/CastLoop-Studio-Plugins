# 生成与验收 1.1

保留下列视觉门槛；正式接入额外执行 [宿主协议](宿主协议.md)、[商业与权益](商业与权益.md) 和 [存档与发布](存档与发布.md)。只测试修改相关玩法、共享模块及其受影响使用方，未特别要求不跑全量仓库测试；不自动维护工作日志。旧示例测试记录不等于当前版本或真机验收。

1. 确认输入与范围，按低保真列页面、状态及相互转移。确认哪些组件来自现有系统。
2. 固定规则与视图插槽，按主题包生成图片、字体及文案。原图留在私有工作区，全部运行图片转换为 WebP，保留透明和原显示尺寸，同步更新运行时映射。
3. 运行 `assemble-runtime.mjs <项目目录> <故事资产根目录>`，自动输出 `mini-games/<gameId>/<gameVersion>/`。逐个游戏装配并检查互不覆盖、互不跨目录引用；已有版本目录不得覆盖。脚本读取游戏清单校验资源并记录文件哈希，美术生成、页面实现和玩法规则由 Agent 根据输入完成。
4. 浏览器走查至少一个完整回合；覆盖首屏、目标、关键操作、失败、恢复、返回剧情，按适用项检查付费与广告。真实测试失败后展示缺少物件。
5. 检查三宽度、各语种字体及最长文案；验证场景可读性、四角一致、边缘不裁切、面板留白、按钮同档成套、位移与微动效分层。
6. 验证主题和语言切换保持进度，玩法切换分开保存；比较引擎哈希。按项目记录已验证和未覆盖项。
7. 输出全局规范、玩法定义、故事包、固定程序、Skill、可运行预览、资源与提示词、生成清单和验证记录。

## 新故事交付门槛

- **创作端产物**：按 [创作端生成与资产复用](创作端生成与资产复用.md) 校验 H5、miniGameData、displayName、editorSchema 一致。用默认值、作者显式 0/false、可编辑字段边界实际初始化游戏，确认 H5 真正读取参数；同一素材在两个节点设置不同关卡，保存重开后互不覆盖。成功结果可从项目素材库找到，不依赖当前节点的短期任务列表。缺少 Runner、资源存储或模型配置时标明未联调，不以模拟成功替代真实生成。

- **格式与目录**：浏览器网络面板实际加载的图片均为 WebP，响应可解码；检查 alpha、原像素和显示大小、九宫格接缝及适用的动画。包内无 PNG／JPEG／SVG 等原稿和非 WebP data URI。至少验证同一故事放入两个游戏，各自在 `mini-games/<gameId>/<gameVersion>/` 中使用自己的配置与资源，没有覆盖、串图或对另一个游戏目录的引用。

- **素材**：在浏览器检查每档实际加载场景，信息区、操作区和适用弹层确实使用九宫格，游戏目标与场上物件实际显示生成图片。检查网络响应、图片解码和渲染来源；有 CSS 或字符占位的项目标为待完成。源设计指定直接复用的演绎示例和系统组件按来源交付。
- **字体**：从故事输入明确每个语种的字体家族与字重。例如指定 Lexend Medium 的英文使用 Lexend 500。玩家区统一从故事字体变量继承；按钮、表单、数字、强调文本和弹窗不得被浏览器默认样式或旧主题覆盖。审核标题、进度、按钮、物件名、工具、教程、救援、失败、Toast 与购置状态。图标使用单独资源。系统组件只有源稿明确规定独立字体时才列出该例外。
- **浏览器证据**：先加载指定 font face 并检查该语种实际文案的字形覆盖。再查关键节点计算字体和字重，有 Chromium 调试接口时用 CSS.getPlatformFontsForNode 核对实际使用字体。缺字、加载失败或意外回退必须补字体资源或修正样式；不能仅凭 CSS 声明判通过。

有 Playwright Chromium 时，导入 `scripts/audit-player-fonts.mjs` 中的 `auditPlayerFonts(page, { family, weight, renderedNames, exceptions })`。逐一进入玩家状态，保存 `checked` 与 `issues`；任何 issues 均需处理。family、weight 来自故事输入，renderedNames 只列同一指定字体的内部家族名或 PostScript 名，exceptions 只列有来源依据的例外。不要用实际测出的回退字体反过来当作预期。

- **主题色**：针对至少一个与参考故事不同的色相，在浏览器核对当前主题的主色变量、信息面板叠色、操作区、主次按钮、弹层及反馈的计算色，并目视检查实际加载的场景、面板和物件原图。主题选择器色块和 CSS 变量正确时，仍需检查图片是否残留旧色相。

- **每个面板分别核验**：逐档进入目标、主游戏、说明、换料与失败等实际画面。确认九片有实际像素并已解码，面板与叠色的透明外沿可见下层，检查四边无黑条、物件无黑底。适中档也要检查细边和面板纹理可辨，不能只确认 URL 成功或用纯色回退截图作为通过凭证。

- **Merge-2 新局首屏**：用新会话打开预览，第一屏须直接显示含目标图与唯一开始按钮的弹窗。验证点一次 Start 即进入可操作棋盘；截图中不得有生成的封面或旁白中转页。

- **页面背景比例**：逐档核对 scene 实际文件为 9:16 竖幅，且与 panel 文件分开。用约 375×812 的预览检查等比 cover 后的左右裁切、场景焦点和阅读区域。

- **清晰度和图标**：在 2×、3× 设备像素比下按原始截图像素检查短面板、操作区、弹窗。对照每片 naturalWidth/naturalHeight 与实际显示尺寸，记录边线发糊或源像素不足。检查返回、重开、帮助在明暗背景及交互态下的透明热区、投影和焦点。

- **固定色门槛**：运行 `node scripts/audit-theme-colors.mjs <项目目录>`，严格装配也会执行该检查。主题色从配置注入，CSS 只用主题变量及其派生色。扫描覆盖 CSS 与 HTML 样式；脚本绘色、外部 SVG 和栅格图仍要检查来源和实际效果。系统付费组件固定色、危险警戒色是明确的例外，通过专用语义变量隔离。
- **换色回归**：同一结构至少用两种不同色相试跑。验收主次按钮及禁用、选中、焦点、按下等状态，同时核对场地叠色、导航、弹窗、Toast、光晕、目标、换料和救援；只检查默认画面不能判通过。
