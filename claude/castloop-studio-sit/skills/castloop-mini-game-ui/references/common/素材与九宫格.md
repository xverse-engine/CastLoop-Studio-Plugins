# 素材与九宫格 1.1

## 最终资源格式与归属

小游戏最终使用的图片统一为 WebP：场景、封面、面板、九宫格九片、物件、图集及图片图标均适用，包括由 SVG 等矢量原稿导出的图片。原稿和去底／裁切中间图可以是 PNG 等格式，但只留在私有工作区。完成加工后转码为真正的 WebP，同步更新 `runtimeFiles`、主题／九宫格／物件映射及 HTML、CSS、JS、JSON 引用；禁止仅修改后缀，禁止运行时仍请求旧图。文字与普通 CSS 布局不属于图片资产。

透明面板、切片、图标和物件优先无损 WebP，保留 alpha、像素尺寸、切线和原逻辑显示大小；场景图可按清晰度选择有损或无损压缩。转码后重新解码核对透明外沿与九宫格接缝，需要动图时验证动画 WebP。每个游戏的图片随该游戏存于故事资产的 `mini-games/<gameId>/<gameVersion>/assets/`，不与其他游戏平铺混用。完整目录和打包入口见 [存档与发布](存档与发布.md)。

| 素材角色 | 生成比例 | 运行时处理 |
| --- | --- | --- |
| 页面背景 scene | 9:16 竖幅，例如 1080×1920，画面铺满、无 UI 边框 | 等比 cover 适配约 375×812 的手机容器，预留左右裁切空间 |
| 面板原图 panel | 复用于横竖容器时，裁边后的有效框体优先近方形，宽高比 0.9–1.1 | 按真实轮廓去底、裁边、九切，角饰保持等比 |

页面背景与面板分别生成、命名和映射。375×812 比 9:16 更窄，居中 cover 时左右各约裁掉 9%，关键信息和场景焦点应落在中间约 82% 的宽度内。按 9:16 构图生成，禁止用方图拉伸或事后裁成竖图代替。验收脚本允许实际导出的宽高比相对 9:16 偏差不超过 3%，用于容纳生成尺寸和像素取整。

- 优先读故事封面、简介、调性、主题色及已有定制化 UI 定义。以有限色板选择主题色，按字体目录指定语种字体。先验证故事输入和素材色相，再验收布局。
- 场景使用真实叙事素材，主光、玻璃反光及大面积暗部体现主题色。叙事细节集中顶部与外围；中心与底部降对比、降密度，让前景信息清楚。
- 三档对照时独立定义空间、光照、材质和角饰密度。采用同故事的视觉线索，保留可辨识的轮廓差异。原图、提示词与运行时资产均带稳定名称和来源记录。
- 框体透明外缘、连续低频中心、直线边条。角饰限制在固定切片区内，向内延伸最多到角区宽、高的 85%。长边采用低对比、无独立饰件的直线材质，装饰集中在角区。边上有明显重复花纹、碎片或凸起时，先修原图。
- 四角等比且跨面板统一尺寸。参考实现是源角 320×256 px、显示 28×22.4 px。从同一张原图用两条横切线、两条竖切线切出完整且相邻的 3×3 网格；禁止从边缘中间抽样拼接。每条边只绘制一次，沿长轴适配，短轴与相邻角区对齐；中心用同网格切片填充。禁止平铺、独立居中、遮罩渐隐造成断边。窄信息面板、高操作区和弹层均须检查四角对齐、边线连续、无重复饰件和接缝。
- 同一档可用同源框体区别信息区、操作区及浮层。用透明通道遮罩做柔光提亮或深色叠层。内容距角饰至少 8 px，参考信息面板安全内边距为左右 40 px、顶部 18 px、底部 22 px。
- 物件图以透明图或图集交付，保留安全边距与同级识别度；物理轮廓由程序决定。更换故事须按当前素材槽位出图。

## 新故事的必交付图片

- 每个交付档位包含页面场景图和面板原图，并从面板原图切出九片供信息、操作及适用的游戏弹层复用。CSS 可以负责切片定位、叠色和文字，面板材质必须来自图片。
- 按玩法登记的全部物件槽位生成透明素材。Merge-2 要覆盖当前玩法声明的全部等级（参考实现 H1–H8），保持可区分的轮廓并体现新故事物件。落子、待投、目标、换料及失败缺少物件共用同 ID 图片。同故事内允许在视觉档间共用物件，逐档记录映射。
- 在项目根保存 art-manifest.json。storyId 与 story.json 一致；assets 每条包含 role（scene、panel 或 item）、source（项目内生成原图或图集路径）、prompt（实际提示词）及 files（项目内运行时图片路径数组）。panel 条目同时列原框运行时文件与九片；item 可由同一张图集覆盖多个槽位。路径须对应主题与玩法清单。
- 新故事最终装配使用 `assemble-runtime.mjs`，图片转为 WebP 后列入 `runtimeFiles`，保留工作区的来源与提示词映射并在浏览器核对实际使用的资源。`assemble.mjs --require-art` 仅用于保留的 1.0 兼容预览，不是新资源规则的发布入口。

## 更换故事时的颜色隔离

- 用户给定的主题色是场景、框体、物件和故事 UI 的共同输入。各档在同一故事色系下调整构图、材质和装饰密度；逐档校对主题配置中的 palette，并核对原图与提示词的实际色相。
- 复用参考工程时，逐项检查面板叠色、边框、按钮各状态、物件光晕、弹层蒙层、提示和反馈。主题相关颜色由当前主题变量（参考实现为 --main）派生，保留亮度、透明度和对比层级。发现前一个故事的固定色值时，迁移到变量。系统组件和明确的状态语义色单独管理。
- 旧图自带的色相不会随 CSS 变量切换。新故事重新生成并替换场景、面板原图与九片、物件图，再更新运行时映射。

- Merge-2 的待投球、落地球和救援选中态分别核对。物件原图、球壳、描边与光晕是独立层；球壳和光晕共用当前主题色变量，待投态禁止沿用参考故事的色值。

## 黑边与缺图检查

- 框体外侧四边和四角必须保留真实 alpha。拒绝原图中烘焙的黑底、棋盘格或长条黑边。以透明导出后紧裁到框体有效边界，再重新做连续九切；保留真实角饰与半透明抗锯齿。物件同样必须是透明抠图，禁止可见的黑色矩形底。
- 素材版容器保持透明。叠色逐片以同一张切片的 alpha 为遮罩，不能盖在整个矩形上。纯色容器仅在资源失败时用作回退，验收截图中出现回退须修复。
- 用 Pillow 运行 `python scripts/audit-art-alpha.py <项目目录>`，检查框外四角透明、面板中心可用、九片像素和物件透明。再在浅色与深色底上分别检查四边，辨别残余黑底、过宽透明留边和过暗面板。

物件图的四条外边均须为 alpha 0，生成和裁切后保留透明安全边距。目标、换料、棋盘、失败提示中的物件容器也应透明。逐个把实际物件图放在浅底和深底上检查；黑色矩形、黑边、假透明底、暗色描边残留均不通过。仅有 alpha 通道或几个透明角不足以验收。

## 原图比例与中心底纹

- 同一张面板要复用于短信息面板、高操作区和弹窗时，原图有效框体优先生成近方形，目标 1:1，宽高比建议 0.9–1.1。以透明裁边后的有效框体计算。角饰固定等比，边条只沿长轴单次适配。
- 方形原图也会遇到极宽或极高的容器。中心纹理应是无方向性的低对比细纹；参考实现中心主体以等比 cover 裁切，保留 6 px 过渡带与连续九片边界接合。不得让整块中心随容器分别拉宽、拉高。若有明显接缝，先处理原图边缘与中心的色差，再验收。
- 目视验收短、长和弹窗三种比例，深浅底与窄屏均要覆盖；中心出现竖纹、横纹、接缝或角饰碰内容时，判为未通过。

## 生成画布到运行时面板

1. 原图与运行时分开保存。生图要求框外留一圈透明间距，外轮廓内侧的镂空也应透明，保留框内底纹。
2. 生成后在浅底、深底上检查沿整个金属外轮廓是否有黑底、青色矩形底、外溢或伪透明。发现时由 Agent 自动调用图像工具去底，按框体轮廓保留内部材质与角饰，复检再继续。禁止只按矩形裁掉四周或按颜色全局删除，以免误伤中心和边饰。若无法可靠去底，标记素材未通过。
3. 使用 `python scripts/prepare-panel.py <透明原图> <assets目录> <档位ID> <角宽> <角高>`（Pillow）裁掉有效框体之外的画布，保留 2 px 抗锯齿余量，并输出连续九片和 nine-slice.json。根据实际角饰终点选择切线，边条中间保留纯直线。脚本拒绝明显不透明外角，但外轮廓是否贴合仍需看图。原始生成图只作来源，不得直接铺满界面。
4. 三档分别验证。检查浅深底下框外镂空露出页面、无背景色块残余，九片边线对齐，中心 cover，短面板、高操作区和弹窗均无装饰变形。

## 清晰度与多倍图

- 按逻辑尺寸与设备像素比交付。实际 App 若按倍数加载资源，提供 2×、3×；若运行时可按目标尺寸采样，可提供一份像素充足的高分辨率原图。1×、2×、3×保留相同逻辑切线与角尺寸。以 28 px 显示角为例，2× 至少 56 px，3× 至少 84 px。
- 单独核对每个角和每条边。需要保持锐度的轴，源切片像素应覆盖该轴实际显示逻辑尺寸乘目标 DPR。高操作区优先核对竖边的有效高度；整张图的分辨率无法代替单片检查。源片不足时用更高分辨率素材或调整切线与构图，单纯放大导出不会补回细节。
- 保留高分辨率母图，直接从母图切出保留 alpha 的 PNG。禁止中间先缩成 1× 或反复压缩。生图保留高对比的窄边和清晰角饰；平直边条避免放中央宝石等随长轴被拉变形的细节。边框本身禁止 blur 或低分辨率画布二次缩放；弹窗蒙层的背景模糊单独处理。
