# 玩法接入契约 1.1

保留 1.0 模块接口，正式接入增补 [宿主协议](宿主协议.md)、[商业与权益](商业与权益.md) 和 [存档与发布](存档与发布.md)。下文参考项目是兼容预览；其中本地模拟不得直接成为正式结算。正式外壳在 mount 前连接宿主，在 ctx.host 注入业务能力，存档由宿主提供。

准备输入、交给 Skill 和控制改动范围的步骤见 [玩法迭代操作指南](玩法迭代操作指南.md)。

| 层 | 负责 | 新故事 / 新玩法时 |
| --- | --- | --- |
| 外壳 | 手机容器、导航、目标、弹层、语言、主题切换 | 复用共用界面；按新玩法槽位增量适配 |
| 玩法引擎 | 输入、状态、判定、计时、快照 | 每玩法一个模块，可独立更换 |
| 玩法视图 | DOM、输入映射、引擎事件、反馈 | 每玩法独立适配；清理监听、动画帧和计时器 |
| 故事包 | 文案、色板、场景、面板、物件、剧情映射 | 按故事替换 |
| 宿主 | 广告、付费、剧情树、结果回传 | Demo 本地模拟；正式接入用宿主回调 |

旧参考工作项目中，`games/<id>/` 放引擎和视图，`games/registry.mjs` 负责登记，`project.json` 声明引擎、视图及素材槽位。该工作区结构不能代替最终故事资产归档：新游戏以独立 `game-package.json` 装配到故事资产的 `mini-games/<gameId>/<gameVersion>/`，代码和全部资源随游戏隔离，运行图片统一为 WebP，详见 [存档与发布](存档与发布.md)。注册项包含展示名、规则简介、`mount`、目标映射和按需填写的关卡标签、导航策略。增加玩法时同时补齐玩法定义、注册项、资源依赖和对应语种文案。移除玩法时从注册表及项目清单移除条目。

`mount(ctx,saved)` 返回 `render / begin / pause / restart / snapshot / destroy`。视图可通过 ctx 使用共用按钮、素材、弹层、保存和路由方法；调试可选实现 `previewFailure`。外壳复用目标与导航，但玩法自定义 DOM、CSS 和语义文案仍需实现。参考运行时不是任意玩法的零代码解释器。

`story.json` 提供独立故事 ID、演绎参考图、物件别名与剧情映射；`story-copy.mjs` 放故事文案；`themes.json` 与 `assets/nine-slice.json` 负责美术。存档按故事 ID 隔离，玩法状态按玩法 ID 隔离。规则变更须定义快照兼容或恢复路径。生成清单记录每个引擎哈希。
