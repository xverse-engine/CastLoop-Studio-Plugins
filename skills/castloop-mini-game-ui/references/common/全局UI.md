# 小游戏全局 UI 规范 1.0

小游戏在剧情宿主中作为一次 QTE 或选项。以对应玩法结构稿确定页面与顺序。宿主原有演绎页采用源设计示例或接入宿主。可玩示例的结构覆盖目标、游戏、工具、说明和失败等已定义状态；是否有入口、成功结算、重试或故事树由玩法与宿主定义。

## 结构与交互

- 以 375×812 为设计基准，验收覆盖 320、375、430 px。布局以容器为准，文字可换行，操作区保留足够空间，信息和道具按钮位于面板安全区内。
- 常用信息架构为上方信息面板、下方操作面板。底部说明独立，文字与图标共用一个可聚焦热区。标题和导航图标加轻投影；导航、帮助、工具采用指定 Google Material Symbols 素材。
- 目标弹窗与主界面使用同一进度字段、名称与格式。目标和缺少物件用图像、名称和数量表示。标题、按钮、数量和热区用代码渲染。
- 同一档的主、次、道具、选项按钮共用轮廓，通过材质、填充、描边和亮度区分层级。可用、禁用、选中、焦点有视觉反馈。
- 编辑侧栏的选项先进入待应用状态，确认后切换主题、界面语言和玩法。换主题与语言保留进度，切玩法保存各自进度。测试入口独立于玩家界面。
- 弹层与工具选择暂停玩法计时和运动；后台暂停后恢复同局。游戏失败后的操作须有明确去向，实际动作由玩法和宿主定义。

## 反馈与字体

- 成功、消除、合成等反馈绑定真实事件。位移和反馈动画分层，外层定位，内层做缩放与透明度。支持减少动态效果。
- 短时反馈放在手机画面中心，用与场景区分的浅底深字；Toast 不阻断原操作。
- 玩家区一次只呈现一种界面语言。本地化包括物件、数字、状态、按钮和无障碍标签。英文、繁中、日文按故事包映射字体；切换前检查字形与字体加载。示例中的系统组件及源剧情图遵循其自身设计规则。
- 资源缺失降级到可读文字和可操作的容器。字体加载失败保留当前方案并给出提示。

- 返回、重开和帮助等无底功能图标用透明 SVG 或遮罩，热区在默认、按下、悬停状态保持透明。复杂背景上给图标轮廓加轻量 drop-shadow，焦点用独立描边。遮罩图标将投影加到透明外层，避免投影被遮罩裁掉。源结构稿明确要求有底按钮时，按其组件设计实现。
