# 存档与发布 1.2

## 存档

保留玩法 `snapshot()`，由宿主统一 `loadSave / saveSnapshot`。权威归属键为账号、storyId、nodeId、interactionId、gameId；grantKey 区分权益。版本和 schemaVersion 用于兼容校验，不用于重新赠送次数。正式持久化游戏要求登录，游客不冒用共享账号。只用 storyId + gameId 会让不同插入点或账号串档。

保存使用 revision 乐观并发控制：旧 revision 返回冲突，不静默覆盖其他设备的新档。登录后的访客存档合并、跨设备冲突需给出产品策略；不自动合并余额或权益。localStorage 可作无敏感数据的本地缓存，但不能作为正式权益、广告额度或购买记录的权威来源。退出登录／切账号时清理或隔离缓存。

快照写明格式版本、玩法状态和已应用的 grantId／消费操作，平台权益账本优先。版本升级定义显式迁移；不兼容时提供保留权益的恢复路径，不能因清空玩法档案而让用户丢失已购内容。故事发布版本绑定固定游戏版本，不能直接指向 latest。

## 正式包与静态检查

1.1 新包使用 [game-package.example.json](../templates/game-package.example.json) 所示的 `game-package.json`。协议规范与游戏内容版本分开：specVersion=`1.2.0`，protocolVersion=`1.1`，gameVersion 为作者发布版本。稳定保留 gameId、offerId、grantKey 和 resultCodes。

`runtimeFiles` 显式列出完整运行依赖，包括入口、JS、CSS、JSON、图片、字体、音视频及引擎许可证。输出只复制这些文件；不整目录复制输入原稿、密钥、node_modules、调试工具或创作端私有资料。宿主接入文件由 `hostBridge` 指明，正式包使用 `production/platform`；创作预览使用 `preview/mock`；尚待真机或真实支付验证的接入包使用 `integration/platform`，不得当作可上线包。静态打包不会把 integration 升级为 production。

### 故事资产目录与图片格式

以平台提供的当前故事资产根目录为边界，每个小游戏使用独立 `gameId` 目录，再按不可变版本隔离。不同小游戏即使使用同一种玩法，也分配各自的 gameId；同一个小游戏可由多个节点引用同一固定版本。

```text
<故事资产根目录>/
  mini-games/
    door-lock/
      1.0.0/
        game-package.json
        index.html
        app.mjs
        host/platform-host.mjs
        assets/scene.webp
        assets/items/key.webp
        fonts/...
        generation-manifest.json
    merge-puzzle/
      1.0.0/...
```

每个版本包自包含所有运行依赖，不引用 `../`、其他小游戏目录或外部图片地址绕过打包。工作原稿、提示词、未转换图片与测试代码保留在发布资产外的私有工作区。平台根据故事绑定决定资产根目录，不能让生成代码指定任意磁盘或存储路径。这里定义资源布局，尚不代表创作端上传、托管服务已实现。

全部图片必须是实际 WebP 编码，包括封面／背景、面板及九片、物件、图集和图片图标。PNG、JPEG、SVG、GIF 等仅可作为工作原稿，转换后更新 HTML、CSS、JS、JSON 中的引用，保留 alpha、像素尺寸与九宫格边界；需要动图时使用动画 WebP 并验证播放。运行包不携带非 WebP 原稿，不能仅重命名扩展名，也不能通过非 WebP 的 data URI 绕过要求。

```powershell
node skill/castloop-mini-game-ui/scripts/audit-runtime.mjs <项目目录>
node skill/castloop-mini-game-ui/scripts/assemble-runtime.mjs <项目目录> <故事资产根目录>
```

第二个参数允许包含故事的其他素材和其他小游戏。脚本自动在其下创建 `mini-games/<gameId>/<gameVersion>/`，只要求这个版本目录为空；已有版本不覆盖、不合并，新增内容提升版本后重新生成。生成清单的 `assetDirectory` 给出相对故事资产根目录的位置，`entry`、`hostBridge` 和 `runtimeFiles` 仍相对当前游戏版本包根目录。

两脚本做确定性的结构、相对路径／符号链接、资源存在、WebP 扩展名与基本文件头、非 WebP data URI、版本和基础 Mock 标记检查；正式包额外要求 `releaseEvidence` 指向的 JSON 包含本版本、本协议及通过的项目相关测试结果和需认证渠道。证据文件应只放用于公开分发的结论，不包含令牌或用户信息。生成清单记录实际输出每个文件的 SHA-256、大小和基于排序清单的 bundleHash。

这不是代码沙箱或安全扫描，基本 WebP 文件头检查也不代替完整图片解码与透明、动画验收。不验证任意脚本的真实行为，不因标记或自述 evidence 为 passed 就自动上线。发布服务必须独立执行检查、验证来源、审核内容并按实物包哈希签发准入；不能让客户端作者自签发资格。静态脚本无法推导全部动态 import／fetch 依赖，仍需网络走查发现漏列资源或动态生成的非 WebP 图片。

## 平台发布门槛（需平台实现）

创作端生成任务和项目素材目录的当前约定见 [创作端生成与资产复用](创作端生成与资产复用.md)。生成成功的记录及对应资源必须长期保留，不能按临时任务窗口删除；预览地址不能短期失效后无法恢复。素材是不可变版本，各节点只保存独立配置和受授权的素材引用。`generatedAsset` 是创作草稿字段，不是消费端资源地址；当前自定义素材的消费端登记未接通，带此字段发布会明确失败。不得删除此字段或冒用内置 gameId 绕过发布检查。

发布证据固定包含 `host-roundtrip`、`lifecycle`、`result`；启用 save 时增加 `save`，声明解锁项时增加 `unlock`。每项通过状态必须来自对应版本的实际检查；模板 [release-evidence.example.json](../templates/release-evidence.example.json) 默认 `not_verified`，不可直接改字样冒充验收。

- 在隔离构建环境处理 AI 生成代码，无生产密钥；限制网络、执行时间和输出大小。以独立资源来源部署，宿主限制网络／导航／消息权限。
- 创作预览与正式容器共享渲染和协议，认证实际目标 Web／iOS／Android，覆盖触摸、安全区、后台、音频、关闭与内存回收。每次只测试变更相关玩法及共享模块的受影响使用方，未特别要求不跑全量仓库测试。
- 真正验证首局、成功、失败、存档、取消及所有启用的商业入口；正式环境无 Mock 回退、无调试侧栏。字体、美术仍按原视觉规范逐项验收。
- 发布服务持有商品报价／会员／广告策略，与内容版本关联；服务器为各类业务确定唯一权威方。错误包可下架、回滚，已购记录与有效权益独立保存。
- 明确平台发行审核、隐私、用户生成内容举报／处理、年龄限制、小游戏索引等要求；按投放渠道当前要求核对，不能仅凭 H5 运行方式视为已经合规。

## 玩法参数与恢复

故事节点携带 miniGameData JSON，Runtime 原样储存/下发，H5 按 schemaVersion 解码。二合炼药只接受 mode=story_single_level 和 levelId=1..10；存档带 levelId，恢复时与当前参数及 engine.level 一致，否则拒绝恢复并保留权益。配置或游戏版本不兼容时暂停恢复，需显式迁移；不得静默清档或重新发放免费次数。

平台快照使用 expectedRevision 乐观锁，消费的后状态与余额扣减原子落库。登录切换、跨设备旧会话必须拒绝覆写。小游戏的 localStorage 不能承担账号存档；诊断预览可在宿主命名空间保存模拟状态，必须明确标注。

integration 包可通过静态资源检查和打包，但仍不可上线。production 必须有本版本、实际目标端的独立验收证据；没有 iOS/Android 真机结果就标为 not_verified，不允许复制预览通过记录冒充认证。

## 1.0 迁移

`examples/blood-moon-belladonna/project` 与随包 `preview` 是原 1.0 可玩示例，保留 specVersion=1.0.0、原引擎和原视觉。`assemble.mjs` 仅装配这一类兼容预览，不是正式发布工具。不得靠改版本号把 MOCK_CONFIG／延时广告变成正式能力。

迁移顺序：复制到独立工作项目 → 外壳注入 ctx.host → 逐个替换本地支付、会员、广告、localStorage 和 DOM 结果事件 → 添加 game-package.json → 检查三端宿主与测试 → 新打包工具输出不可变版本。不要在上架期间直接改旧版本资源。
