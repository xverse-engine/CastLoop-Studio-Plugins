# 存档与发布 1.2

## 存档

保留玩法 `snapshot()`，由宿主统一 `loadSave / saveSnapshot`。权威归属键为账号、storyId、nodeId、interactionId、gameId；grantKey 区分权益。版本和 schemaVersion 用于兼容校验，不用于重新赠送次数。正式持久化游戏要求登录，游客不冒用共享账号。只用 storyId + gameId 会让不同插入点或账号串档。

保存使用 revision 乐观并发控制：旧 revision 返回冲突，不静默覆盖其他设备的新档。登录后的访客存档合并、跨设备冲突需给出产品策略；不自动合并余额或权益。localStorage 可作无敏感数据的本地缓存，但不能作为正式权益、广告额度或购买记录的权威来源。退出登录／切账号时清理或隔离缓存。

快照写明格式版本、玩法状态和已应用的 grantId／消费操作，平台权益账本优先。版本升级定义显式迁移；不兼容时提供保留权益的恢复路径，不能因清空玩法档案而让用户丢失已购内容。故事发布版本绑定固定游戏版本，不能直接指向 latest。

## 工程与运行包

以下是集成工程的最小声明示例。入口、桥和封面都应是工程内的真实文件。把游戏使用的其他文件也列入 runtimeFiles。

```json
{
  "specVersion": "1.2.0",
  "protocolVersion": "1.1",
  "gameId": "my-game",
  "gameVersion": "1.0.0",
  "entry": "index.html",
  "hostBridge": "host.mjs",
  "runtime": {"mode": "integration", "hostAdapter": "platform"},
  "capabilities": ["result", "exit"],
  "saveSchemaVersion": 1,
  "resultCodes": ["success", "failure"],
  "commerce": {"authority": "platform", "offers": []},
  "runtimeFiles": ["index.html", "host.mjs", "cover.webp"]
}
```

每个不可变版本使用 mini-games/<gameId>/<gameVersion>/。包内文件使用相对路径。图片使用实际 WebP，封面必须是可解码的静态图。工作原稿、提示词和测试代码留在工程外或不列入 runtimeFiles。组包保留文件字节，在 generation-manifest.json 记录各文件的大小、SHA-256 和整个文件清单的 bundleHash。

preview 使用 mock 宿主；integration 和 production 使用平台桥。production 在 runtimeFiles 声明 releaseEvidence 指向的 JSON，其中包含本次 gameId、gameVersion、protocolVersion、status、targets 和 checks。以真实目标端的通过记录填写 host-roundtrip、lifecycle、result；启用存档时增加 save，声明权益时增加 unlock。发布前验证宿主中的实际效果与路由。
