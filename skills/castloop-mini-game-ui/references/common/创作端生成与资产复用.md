# 创作端生成与资产复用 1.2

用于 Editor 自定义小游戏生成任务：创作者只输入玩法描述，Skill 交付可运行 H5 和配置，平台保存为可复用的项目素材。完整 HTTP、权限、任务恢复和产物结构见 [Skill Runner 接口](Skill-Runner接口.md)。这份接口快照随 Skill 一起交付给开发同事；Runner 是独立执行服务，不是复制 SKILL.md 后自动产生的能力。

## 输入与参数生成

- 以 Server 下发的 storyId/nodeId/interactionId、taskId、skillId/skillVersion 和能力范围为准，不让提示词改写身份、资源白名单或执行地址。
- `parameterMode=generate_from_description`：把作者的玩法描述同时转为 H5 逻辑、完整 `artifact.miniGameData` 和 `artifact.editorSchema`。前端通常提交 `{}`，这不表示最终游戏没有参数，不要求作者补写 JSON。
- 参数逐字段优先级：API 显式 miniGameData 覆盖（包括 0/false）> 描述指定值 > Skill 默认值。对嵌套对象按字段合并，不用 truthy 判断覆盖；不支持的显式参数或矛盾需求报明错误，不静默忽略。
- miniGameData 是公用、不透明 JSON 对象；每款游戏自己定义结构，H5 从宿主初始化消息解析。声明自己需要的 schemaVersion，并验证关卡、难度等合法值；同一包能按不同节点参数打开相应关卡，不把原始 nodeId 或某个固定关卡写死。
- miniGameData 不是权益账本或付费收据。商业策略保留在 benefitPolicy，缺省 10 钻/1 次免费/会员可用/广告可用，显式值优先；广告入口还需宿主的实时可用性。不要把可编辑参数当成付款、会员资格、广告成功或免费次数恢复的凭据。

## 必须输出的元数据

生成结果与 H5 同时交付：`gameId`、`gameVersion`、`protocolVersion:"1.1"`、`displayName`、完整 `miniGameData`、`editorSchema`、`packageRoot`、`previewUrl` 和真实文件清单。具体限制见接口文档。`displayName` 是供素材库和下拉框识别的游戏名称，非空且 UTF-8 不超过 480 字节。

[参数与表单示例](../templates/generated-game-parameters.example.json) 是可直接参考的元数据片段，不是完整 H5 包或成功任务回执；合入 artifact 后还需真实产物 URL、大小和 SHA-256。表单中的控件必须对应游戏实际支持的参数，不能生成没有作用的装饰字段。

`editorSchema` 使用 version=1 和 fields 数组，最多 32 项；确实无需参数时用 `fields:[]`，不要省略或置 null。编辑器当前仅支持以下类型：

| type | 用途 | 限制 |
| --- | --- | --- |
| string | 标题等短文本 | maxLength 可选，1–4000；未指定时最大 1000 |
| number / integer | 时长、数量等 | 有限安全数值，integer 必须是整数；min/max 可选且 min≤max |
| boolean | 是否启用某玩法功能 | true/false，保留显式 false |
| select | 有限关卡、难度等 | options 1–100 项，各含 label/value；value 仅字符串或有限安全数值且不可重复 |

每项必需 path、label、type；可选 description 和适用的约束。path 是 1–8 段对象键数组，不是点号字符串，也不穿越数组；每段非空且 UTF-8 不超过 64 字节。路径须已经存在于 miniGameData，初始值符合类型、界限和枚举。label 非空且最多 120 字符，description 最多 500 字符；路径不重复，禁止 __proto__/constructor/prototype。数字及边界绝对值不超过 9007199254740991。只声明有意义的关键字段，其他数据原样保留。

schema 是声明式数据，不允许 JS、函数、HTML、脚本事件或任意组件。它只约束可编辑字段，游戏仍需校验完整初始化数据及跨字段约束。历史已保存且缺少 schema 的素材可以按默认参数预览；新生成结果必须有 schema，不能让用户用原始 JSON 编辑器弥补。

## 项目素材与节点配置

1. Runner 以同一 taskId 幂等生成、验证并保存不可变版本，成功后 Server 持久化 artifact。项目素材列表来自项目级成功记录，不来自当前作者/当前节点最近 30 分钟的任务列表。项目成员可按权限查看和预览。
2. 游戏代码、配置和资源放到故事资产下独立的 `mini-games/<gameId>/<gameVersion>/`。对外 packageRoot 例如 `stories/42/mini-games/<gameId>/<gameVersion>`，预览入口为该目录的 index.html。所有运行图片实际为 WebP，保留原像素与透明；不得共享其他游戏私有目录。
3. 项目素材库展示 displayName、版本、详情和预览。成功记录及产物需长期保留，不能随临时任务清理；资源 URL 不可短期过期后无法重新解析。重新生成用新版本或新 ID，不覆盖已被其他节点引用的包。
4. 作者在故事其他节点选择素材后，Editor 保存 `generatedAsset:{storyId,taskId}`、游戏版本身份、深拷贝的 miniGameData 和 benefitPolicy。generatedAsset 是平台按授权资产生成的引用，Skill 不伪造、不把任意 URL 塞进草稿。
5. 同一个游戏可以在节点 A 设关卡 1，在节点 B 设关卡 2。修改 A 的字段只改 A 的参数副本，B 和素材默认值不变；刷新、重新登录及恢复草稿后仍然一致。存档和权益仍按账号/storyId/nodeId/interactionId/gameId 隔离，不能因共用素材而共用免费额度。
6. 预览通过授权 `/assets/{taskId}` 查询取回资源地址，核对 gameId/gameVersion/protocolVersion，使用当前节点参数。实际 H5 通过统一宿主协议读取参数；预览宿主模拟结算，Web/App 正式宿主负责真实支付、会员校验和广告回传。

[双节点配置示例](../templates/generated-game-nodes.example.json) 展示同一素材在两个节点使用不同参数。它是配置片段，非完整故事保存请求；taskId 仅为格式示例，实际必须使用 Server 返回的资产引用，不可直接提交此示例或由 Skill 随意生成。

## 当前接入边界

当前支持生成、查询、项目素材库、跨节点下拉选择、关键参数表单、草稿保存和沙箱模拟预览。新增创作入口仅前端 SIT 展示；后端接口不裁剪环境，不把环境限制写进 H5。

消费端登记和自定义包正式发布尚未接通。含 generatedAsset 的发布请求会明确失败；不要删除该字段、套用内置游戏 ID 或把 previewOnly 改为 false 绕过检查。需要正式故事可玩时，先完成平台登记与对应发布/运行链路，并实测目标端。这里的说明不限制已登记二合游戏的现有接入。

## 交付验证

- 用最终 miniGameData 初始化真实 H5，测试默认关卡及至少一个不同关卡/难度，验证 schema 控件确实影响玩法。覆盖作者显式 0/false；无效参数应有错误反馈而非回到默认关卡。
- 验证两个节点复用同一版本、分别保存参数、恢复草稿，原素材默认值与另一节点不变；确认资产列表跨作者/节点可见但跨项目无权限不可读。
- 验证提交重试不重复生成/收费，关闭后能查询原 taskId；成功资源及记录不依赖短期任务窗口。
- Runner 验证真实文件 MIME、WebP 解码/尺寸/透明、资源引用、大小/哈希、隔离通信与宿主回调，再报告 succeeded。元数据示例和静态检查不证明真实生成或支付成功。
- 仅验证这次修改相关模块；缺少模型、Runner 或资源配置时明确未联调，不自动部署或产生真实支付，不编写工作日志。
