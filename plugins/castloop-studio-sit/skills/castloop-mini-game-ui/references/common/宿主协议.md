# 宿主协议 1.1 / 内容规范 1.2

通信协议版本继续为 1.1，内容包版本为 1.2.0，游戏版本独立管理。注册的二合炼药使用平台宿主；密码锁保留原简化协议。实现参考 assets/host-contract/host-api.d.ts。

Web 在 sandbox="allow-scripts" 的 iframe 内运行，校验 source 后传递私有 MessagePort；不能拿 opaque origin 的 null 字符串当身份。App 使用专用 WebView，只允许固定注册入口，不继承主业务登录/IAP桥。账号凭证、商店收据、广告 SDK、任意 URL 代理和原生方法不进入 H5。

信封含 protocol=castloop.game、protocolVersion=1.1、sessionId、requestId、type、payload。应答含相同关联字段及 ok/data 或 error.code。相同请求号与相同内容重放返回原结果，复用请求号修改内容拒绝。旧会话销毁后不得执行迟到回调。宿主锁定当前用户、故事、节点、互动和已发布配置；H5 不能覆盖 scope、报价或会员状态。账号切换必须重建上下文。

初始化：connect 获取 initialParams（即 miniGameData）、save、offers、showRewardedAd、result 和待恢复操作；ready 开启操作通道；恢复 pendingOperations、取消未提交的旧 reservation 后再允许玩家输入。已经提交的消费按平台快照恢复，不能回滚消费再恢复旧快照。

宿主在后台、支付、订阅、充值和广告中发送 pause，游戏暂停输入、物理时钟和声音；所有中断结束后才 resume。capabilitiesChanged/contextChanged 触发重新读取 context。visibilitychange 也保存快照。destroy 清理所有监听、动画和回调。

H5 的 requestUnlock 只传 offerId，由宿主展示真实可用方式并管理购买 operationId。H5 只可 createOperation(kind=consume)，不能创建或确认 unlock 订单。普通账号服务、广告验证和扣款始终在宿主/服务端。宿主只能把平台明确的 granted 作为成功，超时按原 ID 恢复。

submitResult 只含本包声明结果：success/failure/skipped。skipped 必须已有原子提交的 skip 消费，服务端幂等接受后宿主走发布连线；H5 不能指定 nextNodeId。客户端普通成功结果不是排行榜或资产发奖的反作弊证明。requestExit 先保存后返回故事；不要自动跳到下一难度。
