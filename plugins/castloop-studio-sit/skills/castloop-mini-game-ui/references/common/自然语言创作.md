# 自然语言小游戏创作 1.2

目标用户不懂代码。只有自然语言想法而没有 UI 框架、规则文档时，Agent 负责整理玩法目标、输入、胜负、页面状态和素材槽位；结构稿／技术文档不是用户开始创作的前提。只对影响玩法、商业规则或故事去向的关键缺项提问，其余合理默认值明确展示在可编辑草稿中。

## 工作方式

1. 读作者授权的当前故事节点和现有素材，输出简短玩法说明及待确认商业项。已有适用玩法可复用；新玩法按接入契约实现独立引擎和视图，不承诺任意复杂游戏一定生成成功。
2. 先生成可玩的单一默认主题版本，作者要求视觉档位对比时再扩展。保留原素材与字体门槛；若暂缺生图能力，可提供明确标注的技术预览，不把占位画面当成最终美术交付。
   同时生成与 H5 匹配的完整 `miniGameData`、可识别的 `displayName` 和 `editorSchema`；用户只描述玩法，关卡、难度等重要参数由 Skill 声明为表单控件，不让用户补写 JSON。API 显式覆盖优先于描述和默认值，保留 0/false。具体输出与示例见 [创作端生成与资产复用](创作端生成与资产复用.md)。
3. 支持自然语言局部修改、预览及撤销。保留 gameId、offerId、grantKey、已确认规则、已有素材和存档兼容性；“改提示价格”不得顺带更换玩法和权益 ID。规则变化才更新引擎；视觉修改前后比较引擎哈希。
4. 成功／失败／退出结果在编辑器连接到故事节点。价格、会员和广告条件由平台规则约束，AI 提交配置草稿而非自己批准商品或创建真实订单。
5. 自动检查后试玩，发现具体错误最多自动修复两轮；仍失败则保留最后可用版本并说明阻塞，不无限生成。验证仅覆盖变更相关模块，不执行真实扣款、不发布上线。

## 产物与权限

作者界面显示玩法、预览、修改入口和版本，不强迫用户阅读代码与构建细节。开发交付保留项目与资源声明；运行时包排除提示词原稿、私有输入和调试资料。执行生成代码应使用隔离环境，不给平台服务器密钥。Skill 只指导生成，不能代替平台发布审核。

生成成功不自动覆盖当前互动。平台将不可变游戏素材加入所属项目素材库，作者在任意节点的下拉框选择后，各节点保存独立参数副本。改节点参数不修改原素材，原包及版本保持可恢复；重新生成代码使用新版本或新 ID。当前自定义素材仅接通草稿与预览，消费端登记完成前发布明确失败。

不编写、追加或维护工作日志。只有用户明确要求时才输出工作日志；机器生成清单、测试结果和本次明确要求的版本说明属于交付物，不自动扩展成持续维护记录。
