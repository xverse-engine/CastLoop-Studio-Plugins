# 通用权益 1.2

默认 10 钻、1 次免费、享受会员权益、允许激励广告。作者指定优先，0/false 不是缺省值。策略在服务端发布配置内，H5 仅展示 context/getOffer 返回的实际报价和可用方式。节点单项 > 节点统一 > 游戏单项 > 游戏统一 > 默认，逐字段合并；禁止用 || 合并数值/布尔参数。

每个玩法声明稳定 grantKey、offerId、kind 与效果；例如 clear/swap/retry 是次数，skip 是本插入点通关权益。新类型由注册表声明，不把特定玩法的 clear 等字段添加到 Runtime 故事表。平台通用维护余额、赠送、领取、预留、消费和结果；H5 使用通用协议，自行实现消除、提示等效果。初期接入只开放已经审查注册的游戏/权益，新增声明不是自动获得平台能力。

scope=interaction，权威键是 userId+storyId+nodeId+interactionId+gameId+grantKey。章节 1 的免费次数用完不影响章节 2；在章节 1 关闭重开、清缓存、跨设备或重新登录不补发。同章重试不补发道具。游戏版本/会话不是赠送键。自定义 account/story 等范围需单独实现并验收，不能混用本协议的章节语义。

平台流程：context → 用户操作 → requestUnlock(offerId) → 宿主确认方式 → 服务端创建并持久化原 operationId → 核价/扣钻或会员校验/广告奖励结算 → granted。未使用余额立即持久化。响应丢失按原 ID 查询，禁止自动新建订单重扣。会员每次领取重新校验有效期；开通会员或充值通过宿主既有弹窗，返回时刷新资格，仍由用户确认下一次操作，不自动转成扣钻。

使用流程：保存当前快照 → createOperation(kind=consume,key) → reserveUse(operationId,expectedRevision) → 在候选状态执行效果 → commitUse(reservationId,expectedRevision,data,resultCode?) → 接受服务端新 revision 后替换可见状态。无效目标/取消取消预留；提交结果未知时先查权威快照，再决定是否取消，绝不能盲目补次数。commitUse 把消费与效果快照放在同一事务，重复提交不重复消耗。崩溃前已提交就恢复新档，未提交就释放预留并保留次数。

广告入口可用性 = 配置允许 ∩ 当前渠道能力 ∩ SDK 就绪 ∩ 剩余额度。showRewardedAd 在打开时提供，能力变化再刷新，点击前重查。关闭/点击/展示/无填充都不是奖励。仅在 SDK 的奖励成功回调后由宿主记录待结算回执，按同一 eventId 结算，断网后恢复；回执留宿主且隔离账号。生产仍使用平台既有广告验证策略，不能把客户端回执宣称为广告平台服务端验证。

验收仅用 Mock/SIT：0/false 覆盖、非会员与过期会员、扣款回调丢失、未用权益退出恢复、无效目标取消、消费提交丢失、跨章节与跨账号、并发旧 revision、广告取消/无填充/迟到成功/重复回传。不得使用真实玩家余额做测试。
