# CastLoop Studio 正式版 MCP：Agent 冒烟测试

基础冒烟适用于正式插件 1.0.0 起；本次 1.0.1 配套新增项在后端部署后按[两批对齐增量](mcp-sit-acceptance.md)执行。目标是粗测核心链路，测试前核对实时 schema。

## 环境和执行边界

- 正式插件：`castloop-studio`；MCP：`https://studio.castloop.ai/mcp`；授权发行方：`https://auth.castloop.ai/oidc`。
- 只使用当前会话实际暴露的正式 MCP 工具。SIT 工具不能代替正式工具；先确认工具来源，再调用。
- 工具名和参数以实时 schema 为准。缺少工具记 BLOCKED，不能根据本文或本地代码声称可用。
- 用户按本文授权后，可创建专用测试故事并执行下表中的小规模写入、复制和导入；不得编辑已有业务作品。
- 每轮使用唯一 runId，例如 UTC 时间加随机后缀；测试作品统一前缀 `MCP正式验收-<runId>`。
- 全程保留测试作品供人工检查，不发布、不自动删除，不改账号权限，不制造供应商或网络故障。
- 同一测试故事不要同时在 Studio 中编辑；MCP 只读取线上已保存内容。测试完成后再打开或刷新 Studio。
- 默认不调用模型。付费小样需用户明确授权：最多 1 次短文本生成、1 张道具图；提示词准备可能另有文本费用。失败不自动重试，不生成视频、音乐、语音、整批图或剧情子图。
- 写入参数支持 requestId 时使用稳定 ID，保存参数、返回 ID 和回执。超时先查询/读回，不能更换 ID 盲目重做；不要为验收主动重复收费请求。
- `composeStoryFlow` 的精确节点、选项和对白操作应省略 `requestId`，只有 `generateSubgraphs` 使用它。精确编辑缺少幂等保护，结果不确定时先读回。若服务端明确拒绝该参数并确认未保存，移除该字段后可重试该次调用。旧版本仅返回通用 `invalid_input` 时先读回确认，再调整调用。
- 仅文件下载和签名上传可使用本地 HTTP 客户端；禁止绕过 MCP 直接调故事保存或生成 API。

## 测试清单

按顺序执行；单项失败保留证据，能独立继续的项目继续。没有执行的项目不能记 PASS。

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| A 连接与发现 | 列出当前正式工具名称，调用 `listStories` 读取一小页作品元数据 | 正式工具可用且真实读取成功；不以插件已启用或网页可达代替。不得读取其他业务故事正文 |
| B 新建与定位 | `createStory` 新建中文测试故事，记录 storyId；用唯一名称搜索，按需翻页；用 `readStorySections`、`readStoryCharacters` 读基线 | 返回的新 ID 可被搜索并独立读回；能读取起点、旁白和空资产。之后所有写入固定这个 ID |
| C 角色与资产文字 | 用精确 updates 创建 1 个普通角色、1 个地点、1 个道具，再改角色名字或人设；设置一小段世界观和大纲 | 按实时 schema 操作并分别读回；名称、文字、数量正确，旁白保留。角色使用 `ttsLanguage=other` 且不传生成 fields，避免自动选音色。其他操作也只用精确值；若必须调用模型，则跳过并说明 |
| D 剧情编辑 | 在新故事中用 `composeStoryFlow` 创建 2 个普通节点，设置一条 A→B 的选项和一小段角色对白；修改选项文案/对白后读回 | 节点、连线目标、选项文字、角色 ID 和对白与预期一致；起点保留。使用实际返回的节点/选项/组件 ID，不猜 ID；不必测删除、级联或 QTE |
| E 复制 | 用 `copyStory` 将测试故事复制为另一个带 runId 的故事，并分别读取源与副本 | 新 storyId 与源不同；角色、地点、道具、世界观、大纲、节点和剧情去向保持语义一致；源故事不变。允许内部 ID 重映射 |
| F JSON 往返 | `exportStory` 导出源测试故事，直接下载到本地；用 `prepareStoryImport` 获取上传地址，按全部返回 headers PUT 原文件，再 `importStory` 创建新故事 | 文件不塞进模型上下文、不转 base64；新 ID 不同，剧情去向、对白、角色和资产文字与源一致；原故事不变。按实际 schema 提供同一操作稳定 requestId；缺少本地上传能力记 BLOCKED |
| G 付费小样（可选） | 用户授权后，在源测试故事调用一次 `generateMedia` 生成约 50 字中文短句；调用 `generate_item_images` 为测试道具生成 1 张图，使用 `fill_missing` | 保存 taskId；分别用 `readMediaTasks`、`readImageTasks` 查到最终成功；道具图片已应用，独立读回有图片 URL。通用文本结果不应被自动当成故事正文已保存。accepted/排队/生成中都不算完成 |
| H 任务读取 | 用 `readGenerationTasks` 查询本轮 taskIds；若未执行 G，仅验证测试故事的任务读取正常 | 与本轮已知任务对应；无任务可以返回空列表，但不能因此声称生成或任务恢复通过。无法观察取消/重试则留待后测，不主动制造失败 |

C/D 的具体读回入口由实时工具说明决定，例如节点内容读取工具；不能用写入响应重复解释来代替另一次读取。

E/F 对比的是用户可见内容及连线语义，不要求故事 ID、节点 ID、资源路径完全相同。临时签名链接和 uploadId 不写进报告。若导入返回缺图或路由错误，报告原因并停止该步骤；不自动开启缺图继续，也不修复业务原文件。

G 每 10–15 秒查询一次，查询接口失败不等于生成失败。最多观察约 15 分钟；未完成记录 PENDING，并保留 taskId 供后续查询，不能宣称失败或另发生成。只有成功且应用完成才能记道具生图 PASS。生成后可再导出、导入一次验证带图往返；这是扩展项，不强制重复 F。

## 授权与续期

若正式工具为 0 或出现 `Insufficient scope` / 登录过期：停止正式写入，报告客户端原始错误与发生阶段，提示用户通过 Codex 的正式插件/MCP 设置重新认证；不编造授权 URL，不索取密码、Token 或密钥。重新认证后续测，不使用 SIT 兜底。

本轮短测不能证明自动续期。等待访问令牌自然到期后再做一次正式只读调用；没有经过该过程或没有对应审计证据，则记 NOT_OBSERVED，不要求退出登录来伪造续期。

## 留给用户的人工检查

Agent 完成后只给出本轮实际创建的作品 ID/链接及以下简短清单：

1. 打开源测试故事：普通角色、地点、道具、世界观和大纲正确；A→B 连线及对白可见。
2. 打开复制故事与 JSON 导入故事：内容与源一致，可以继续编辑；原故事未被替换。
3. 若执行 G：道具图出现在资产详情和画布，连线/采用图正确，刷新后仍在。
4. 从国内/海外 Studio 首页打开 Codex，目标 MCP 均为正式海外地址；从故事内打开时目标 storyId 正确。此项需用户主动操作，Agent 未观察不得记 PASS。

本轮不覆盖：多账号隔离、多人同时编辑、发布、服务重启/断网恢复、费用逐笔审计、所有五类图片、全部独立生成类型。历史 SIT 通过可引用为历史证据，不能改写成本轮 PRD 已测。

## 报告

报告保存到用户指定的本地私有位置。默认可使用 `F:/xnarrator/Editor_2/outputs/mcp-prd-smoke-<runId>.md`；目录不可访问则在对话返回，不私自改为公开仓库。

记录：时间、runId、实际插件/服务版本（无法获取写未知）、MCP 地址、正式工具名称、本轮创建的 storyId/节点 ID/taskId、各项 PASS/FAIL/BLOCKED/PENDING/NOT_OBSERVED/SKIPPED、断言与独立读回证据、付费请求数量、残留作品、人工待查项。

不得保存密码、Token、签名上传/下载链接、完整业务存档或其他用户资料。少量作品列表只用于验证，不把业务作品名抄入报告。报告不提交公开 Git。
