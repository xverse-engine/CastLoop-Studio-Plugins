# 自定义小游戏 SIT 专项验收

适用于 CastLoop Studio SIT 插件 0.1.20。用同一个自定义 H5 包走完 MCP 创作、资产入库、节点应用和消费端播放。本文是操作用例，线上各项初始状态均为待测。

## 测试准备

- 记录实测日期、Codex 中启用的插件版本、SIT 编辑器前后端版本、Runtime 和消费端实际镜像。打开 SIT 插件会话，确认能读取 `castloop-mini-game-ui`；记录当前连接实际返回的工具名。
- 准备有编辑权限的测试故事 A、可发布的 SIT 测试版本、两个可添加互动的 section 节点，以及用于验证跨故事复用的故事 B。在 A 中记录节点原有交互、预期触发时间、胜负后的预期去向。
- 给测试游戏加一个肉眼可辨的标记，例如标题「月灯试验」和自带的月亮图。设计一条可重复触发的成功路径和失败路径，选一个在 `editorSchema` 中声明、调整后能看出效果的参数。随后每个试玩入口都核对这个标记和参数。

## 操作与通过标准

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| 01 读取故事与设计 | 在 MCP 中指定故事 A 和节点，提出玩法需求，刻意留下一项影响胜负的设计问题。用 `readStorySections` 和 `readStoryNodes` 核对上下文。 | Agent 使用指定故事的信息，沿用原版设计提问，按回答制作。适用素材优先复用，缺图时优先使用 agent 能力。若实际走 Studio 兜底，记录授权、`generateMedia` 任务 ID 和 `readMediaTasks` 结果。 |
| 02 本地成品 | 按制作指引生成版本目录并试玩。由该目录生成 ZIP，计算 ZIP 的 SHA-256，记录大小和版本。 | 根层有 `index.html`、`generation-manifest.json`；相对路径素材能加载，胜负可触发。压缩包及解压后运行文件各不超过 20 MiB。去向未定时，成品完成后再选择去向。 |
| 03 上传到项目库 | 要求“只存入故事 A 项目素材库”。调用 `prepareMiniGameUpload(bytes)`，按回执方法和请求头上传原始 ZIP，再用 `importMiniGame` 提交 `library=project`、`storyId`、`uploadId`、显示名、玩法数据和参数 schema。 | 上传成功后取得 `assetId`，用 `listMiniGames` 在 A 项目库读回名称和版本。读回两个节点，原有交互保持原样。若提供的权益配置含显式 0 或 false，读回值与输入一致。 |
| 04 资产库独立试玩 | 在项目素材库找到刚导入的资产，右键「预览」。随后用 `copyMiniGame` 从 A 转存到个人库，传入 `sourceStoryId`，目标为 `library=personal`。从个人库再次打开预览。 | 两个入口都能在未绑定节点时启动，显示预定标题和图片，响应操作。分别记录两库读回的资产 ID，转存过程中仅上传过一次 ZIP。 |
| 05 应用与参数隔离 | 先读 A 的两个节点，再分别用 `applyMiniGame` 指定项目资产、`storyId`、`nodeId`、空闲正整数 `interactionId` 和已核实的对白、视频段内时刻或节点出口。工具不能表达该位置时记录 BLOCKED 并跳过写入。原样重试其中一次。在编辑器只调整第一个节点的测试参数并保存。 | 用 `readStoryNodes` 读回两处 `generatedAsset` 和实际位置。无法对应真实内容、显示「待定位」或「超出当前内容」即判 FAIL。每处只有一个新增交互，原有交互仍在。刷新后第一个节点保留新值，第二个节点和库内模板保留默认值。 |
| 06 节点与整篇试玩 | 从「试玩此节点」进入第一个节点，再从故事起点按正常路径走到它。分两次触发成功和失败。 | 两个入口都在约定时间打开同一个自定义游戏，显示节点参数对应的效果；结束后按故事配置继续或跳转。记录各自触发的结果和后续节点。 |
| 07 发布后消费 | 将已验收的 A 草稿发布到 SIT。用消费端打开该发布版本，按相同路线重玩。 | 发布编译成功，带自定义包的节点保留。实际播放器能加载入口和素材，参数、胜负和后续跳转与第 06 项一致。记录发布版本及消费端播放证据。 |
| 08 跨故事复用 | 从个人库用 `copyMiniGame` 复制到 B 项目库，目标带 B 的 `storyId`；用返回的目标资产应用到 B 节点。 | B 中可独立试玩，无需重新生成或上传。再次读回 A，核对 A 的资产引用和节点参数仍为第 05 项的值。 |

### 位置专项复测

| 位置 | 正例 | 反例 |
| --- | --- | --- |
| 图文 | 指定内容段、分支和第 2 句对白，确认读完第 2 句才触发。 | 删除对白或只传 triggerAtMs=1000，确认拒绝且节点未变。 |
| 视频 | 指定内容段、分支和段内毫秒，从片头播放核对触发点。 | 超出当前分支视频时长应拒绝；无法读取时长时记录阻塞。 |
| 节点出口 | 指定成功与失败目标，核对内容结束后启动及两条去向。 | 未确认替换已有选项、目标不存在或同时传 anchor 和 exit 时，原路由保留。 |

每个正例原样重试一次，读回实际位置并核对只有一个互动。已有「待定位」的草稿需选定真实位置并重新定位后再验。

## 分支与失败用例

| 场景 | 操作与预期 |
| --- | --- |
| 故事外创作 | 仅提供玩法资料时按原版交付独立玩法包，无需故事 ID。若已有符合第 02 项的可试玩 H5 成品，另测直接导入个人库，`importMiniGame` 使用 `library=personal` 并省略 `storyId`。用 `listMiniGames` 在个人库读回。 |
| 仅保留本地 | 明确要求本地交付，核对本地路径及产物。工具记录中应无上传、导入和节点写入。 |
| 上传或包校验失败 | 用缺少根层 manifest 的测试 ZIP 尝试导入。记录返回错误，再查目标库和节点，确认未产生可选资产或新交互。保留正确的本地包用于重试。 |
| 无效位置 | 测试不存在的对白、越界的视频时间和未授权替换的出口。应在写入前拦截，读回原互动和出口无变化。 |
| 工具缺失 | 核对 `prepareMiniGameUpload`、`importMiniGame`、`listMiniGames`、`copyMiniGame` 和 `applyMiniGame`。缺项时记录实际工具清单及第一个受阻步骤，继续执行可独立验证的用例。 |

## 验收记录

每项填写一行。状态使用 PASS、FAIL、BLOCKED 或 NOT_RUN。失败后重试时保留首轮结果。私有报告保存脱敏的故事、资产、节点与发布版本标识，上传证据仅记录响应状态和包摘要，省略签名地址、令牌及上传凭据。
